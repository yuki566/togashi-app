# 📄 data/ ― アプリのデータの書き方

このフォルダの3つのJSONファイルを直すと、**プログラムを触らずに**アプリの文章やスポットの情報を変えられます。

| ファイル | 中身 | 使っている画面 |
|---|---|---|
| [`questions.json`](questions.json) | 診断の質問（6問・各4択） | S2 診断 |
| [`types.json`](types.json) | 4タイプの説明と、おすすめスポット3か所 | S3 結果、S4 一覧 |
| [`spots.json`](spots.json) | スポット10か所の情報 | S4 一覧、S5 詳細 |

> [!IMPORTANT]
> 直したら、**Live Server でアプリを開いて、画面が正しく出るか**を確かめてから Pull Request を作ってください。
> 書き方を間違えると、アプリ全体が「データを読み込めませんでした」になります。

---

## JSON を書くときの注意

| よくある間違い | 正しい書き方 |
|---|---|
| 最後の項目の後ろに `,` がある | `{ "a": 1, "b": 2 }` ← 最後の `2` の後ろには `,` を付けない |
| `“` `”` や `＂` を使っている | 必ず半角の `"` を使う |
| 数字を `"36.52"` のように `"` で囲んでいる | 緯度・経度は数字なので `36.52` と書く |
| `'` で囲んでいる | JSON では `'` は使えない。`"` を使う |

VS Code で開くと、間違っている場所に**赤い波線**が出ます。保存する前に確認してください。

## questions.json（診断の質問）

```json
{
  "id": "Q1",
  "draft": true,
  "text": "あなたの今の生き方に一番近いものは？",
  "choices": [
    { "text": "積極的に周りの人をまとめて、リーダーになる", "type": "統治" },
    { "text": "気になったことはすぐに調べたくなる", "type": "学び" },
    { "text": "どんな困難にも勇気を出して立ち向かう", "type": "武勇" },
    { "text": "大切なものを信じて進む", "type": "信仰" }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `id` | 質問の番号（`Q1`〜`Q6`） |
| `draft` | まだ仮の文章なら `true`、確定したら `false`。今は目印だけで、画面には出ません |
| `text` | 質問文 |
| `choices` | 選択肢。`text` が画面に出る文、`type` がその選択肢で1点入るタイプ |

- `type` には **`統治` `武勇` `信仰` `学び` のどれか**を、そのまま書きます（1文字でも違うと点数が入りません）
- 1問の中で、4つのタイプが1つずつになるようにします
- 選択肢は、書いた順番のまま画面に出ます
- **質問の順番に意味があります**。同点のときは、**最後の質問（Q6）**で選んだタイプが優先されます（[診断のしくみ](../README.md#-診断のしくみ)）

## types.json（タイプの説明）

```json
{
  "統治": {
    "draft": true,
    "title": "まとめ役タイプ",
    "catchcopy": "全体を見て、みんなを導く",
    "description": "物事の全体を見渡して、…",
    "spots": ["守護所富樫館跡", "富樫館跡", "富樫家国像"]
  }
}
```

（実際のファイルでは、このあとに `武勇` `信仰` `学び` が同じ形で続きます）

| 項目 | 意味 |
|---|---|
| `"統治"` など | タイプ名。4つ（`統治` `武勇` `信仰` `学び`）から変えないでください（色の設定やほかのファイルとつながっています） |
| `draft` | `true` の間は、結果画面に「※ この文章は仮のものです」の帯が出ます。確定したら `false` |
| `title` | タイプの名前（結果画面の大きな見出し） |
| `catchcopy` | ひとことの説明 |
| `description` | タイプの説明文 |
| `spots` | おすすめスポット3か所。書いた順に、一覧の先頭に「おすすめ」の印つきで並びます |

> [!WARNING]
> `spots` の名前は、`spots.json` の `name` と**1文字も違わずに**同じにしてください。違っていると、エラーは出ずに、そのスポットが「おすすめ」になりません。

## spots.json（スポットの情報）

```json
{
  "id": "spot-01",
  "name": "守護所富樫館跡",
  "types": ["統治"],
  "address": "石川県野々市市…",
  "lat": 36.5,
  "lng": 136.6,
  "description": "（史跡の解説）",
  "source": "（出典）",
  "photo": "spot-01.jpg",
  "draft": true
}
```

| 項目 | 意味 | 空のときの画面 |
|---|---|---|
| `id` | スポットの番号（`spot-01`〜`spot-10`）。**一度決めたら変えない** | ― |
| `name` | スポット名 | ― |
| `types` | 関係するタイプ（1つか2つ）。**最初に書いたタイプの色**が、一覧の木札の左端の色になります | ― |
| `address` | 住所 | 「（準備中）」 |
| `lat` / `lng` | 緯度 / 経度（数字）。わからない間は `null` | 地図は「スポット名 野々市市」で検索、距離は「場所の情報は準備中」 |
| `description` | 解説。**史実は出典に書いてあることだけ**を書き、創作しない | 「（準備中）」 |
| `source` | 出典（書き方は下） | 「（準備中）」 |
| `photo` | `images/` に入れた写真のファイル名 | 「写真は準備中」の枠 |
| `draft` | 1か所でも `true` があると、一覧に「※ スポットの情報は準備中です」の帯が出ます。そのスポットの詳細画面にも帯が出ます | ― |

### 緯度・経度の調べ方（Googleマップ）

1. パソコンの Googleマップで、スポットの場所を**右クリック**します（スマホは**長押し**）
2. いちばん上に `36.52xxx, 136.60xxx` のような数字が出るので、押してコピーします
3. **前の数字が `lat`（緯度）**、**後ろの数字が `lng`（経度）**です。野々市市なら、緯度は 36、経度は 136 くらいになります

```text
"lat": 36.52xxx,
"lng": 136.60xxx,
```

### 出典の書き方

解説に書いたことの「元」を、あとから誰でも確かめられるように書きます。

| 種類 | 書き方 |
|---|---|
| 本 | 著者名『書名』出版社、発行年、ページ |
| Webページ | サイト名「ページ名」URL（○年○月○日 参照） |
| 現地の説明板 | 「（スポット名）の説明板」（設置者）、○年○月○日 撮影 |

いくつもあるときは、`、` か `／` で区切って1行に書きます。

## 📷 写真（images/ フォルダ）

- **自分たちで撮影した写真だけ**を使います。生成AIで作った画像、ネットから保存した画像は使いません
- ファイル名は、スポットの `id` に合わせて `spot-01.jpg` のようにし、`spots.json` の `photo` に書きます
- スマホで開くので、**長い辺 1600px くらい・1枚 500KB くらい**までに小さくしてから入れます

> [!CAUTION]
> **写真を入れる前に、プライバシーを確認してください。**このリポジトリは誰でも見られます。
> - 通りかかった人の**顔**や、車の**ナンバー**が写っていない
> - 写真の中の**位置情報などの記録（Exif）を消した**
>   （Windows：写真を右クリック →「プロパティ」→「詳細」→「プロパティや個人情報を削除」）
> - 撮影が禁止されている場所（寺社の中など）で撮っていない

## ✅ 仮のデータを本物にするときの手順

1. 自分用のブランチを作る（例：`data/spot-01`）
2. 中身を書く（出典を確認しながら）
3. その項目の `draft` を `false` にする
4. Live Server で、画面の表示を確認する
5. Pull Request を作り、ほかのメンバーに**出典と内容を確認**してもらう
